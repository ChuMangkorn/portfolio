# Work Log Strip Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A strip above the work cards that shows how many jobs the owner's anonymised work log holds, how many were cases and incidents, and a bar of case types, every number from a committed snapshot.

**Architecture:** A pure counter (`lib/worklog-count.ts`) turns month files into counts. A script runs it against the vault and writes the snapshot `lib/worklog-stats.ts` (counts only). `lib/data.ts` turns the snapshot into strip copy; a server component renders it inside `Work()`.

**Tech Stack:** Next 16.2.9, React 19, Tailwind 4, TypeScript run natively by Node (`node --test tests/content.test.ts`).

**Spec:** `docs/superpowers/specs/2026-11-13-work-log-strip-design.md`

## Global Constraints

- The snapshot and the page hold counts and fixed labels only, never text copied from the log.
- Copy says "logged", names the month range, and never says "completed" or "per month". No dashes (U+2013, U+2014) anywhere in copy.
- The strip does not animate (the motion check must stay green). Use existing tokens (`text-fg-muted`, `font-display`, `border`), no new colours outside the theme.
- Work on branch `worklog-strip` from `main`. Do not merge, push or deploy. No `Co-Authored-By` in commits. Do not read `tests/banned.local.txt`, `.gates/`, `.ds-receipts/`, `.env*`.
- Before writing code that touches Next, read the relevant guide in `node_modules/next/dist/docs/` (AGENTS.md).

## Review Focus

- A case entry with no `- type:` line: the counter must throw, not write a bar that no longer adds up (Task 1 test).
- A month file with routine lines but no cases (March): it still counts, and `since` is the first month with any entry (Task 1 test).
- Routine lines with the new ID form `W-261113-1042` count the same as `W-070` (Task 1 test).
- A stale snapshot: the label's end month comes from `asOf`, so an old snapshot reads as old instead of claiming today (Task 2 test).
- Phone width 390: the six-segment bar must not overflow or clip its labels (Task 3 screenshot plus `npm run check` overflow gates).

### Task 1: Counter and snapshot

**Files:**
- Create: `lib/worklog-count.ts`, `scripts/worklog-stats.ts`, `lib/worklog-stats.ts` (generated)
- Test: `tests/content.test.ts`

**Interfaces:**
- Produces:
  - `type CaseType = "build" | "incident" | "fix" | "ops" | "analysis" | "migration"`
  - `type WorklogStats = { since: string /* "2026-03" */; asOf: string /* "2026-11-13" */; total: number; cases: number; routine: number; byType: Record<CaseType, number> }`
  - `countWorkLog(files: { month: string; text: string }[], asOf: string): WorklogStats` in `lib/worklog-count.ts`
  - `export const worklogStats: WorklogStats` in `lib/worklog-stats.ts`

Counting rules: a case is a line matching `/^### \d{4}-\d{2}-\d{2} \|/`; a routine entry is a line matching `/^- \d{4}-\d{2}-\d{2} \|/`; a type is `/^- type: (\w+)/`. Throw if a type is not a `CaseType`, or if the type counts do not sum to `cases`. `since` is the earliest month with at least one entry.

Assert `since === "2026-03"`, `cases === 1`, `routine === 3`, `total === 4`, `byType.incident === 1`, other types 0. Then assert `countWorkLog` throws for a case with no type line.
